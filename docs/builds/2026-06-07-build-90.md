# Build 90 — 2026-06-07

## Headline

Root-cause fix for the stuck/invisible popup on login (the "lucky pig" glitch):
all popups now go through one global queue and show strictly one at a time.

## Root cause

Every popup in the app is a native RN `<Modal>` (LuckyPig, LuckyTitle,
ReleaseNotes, WhileAway, Achievement, Allegiance, Schism, Judgement, the truffle
sheet, the six-seven dialog). iOS presents only ONE modal per window — a second
`<Modal>` set `visible` while the first is still presented mounts but never
presents, staying invisible while it eats touches (the "can't get past it" bug).
Two gaps let that happen:

1. **No coordination across component trees.** Launch modals live in
   `app/_layout.tsx`; the home modals live in `components/Barn.tsx` (a tab). Neither
   could see the other, so a root modal (e.g. WhileAway on login) + a Barn modal
   (ReleaseNotes / LuckyPig) could be `visible` simultaneously.
2. **Lucky-pig burst → title handoff race.** On burst dismiss the code opened the
   title-unlock modal after a hard-coded 280 ms timer, but the burst modal's outro
   animation runs ~600 ms — so the title `<Modal>` presented while the burst was
   still on screen.

## The fix

New `components/ui/PopupQueue.tsx` — a single arbiter (provider at the app root,
above both the Stack and the launch modals). Every popup declares intent via
`usePopupSlot(id, want, priority)`; only the highest-priority waiter is told it's
`visible`, and on dismiss `release()` holds a 380 ms beat so the outgoing modal
fully unmounts before the next mounts. Only one native `<Modal>` is ever visible,
app-wide, which also makes the racy 280 ms lucky-pig timer irrelevant.

Wired through the queue: root (schism/finale/while-away/achievements/allegiance)
and Barn (lucky-pig, lucky-title, six-seven, release-notes, truffle sheet).
Replaces the earlier root-only `modalGap` patch from build 89.
