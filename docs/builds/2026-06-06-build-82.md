# Build 82 — 2026-06-06

## Headline

**Push notifications turned on.** Build 81 + the missing piece: the iOS app can
finally register for APNs. Everything else (permission flow, token storage,
server-side delivery) was already built — this is the entitlement + credentials
that were the actual blocker.

## What changed

- **`aps-environment` entitlement added** to `ios/ttp/ttp.entitlements` and
  `app.json` (value `production` — TestFlight/App Store use the production APNs
  environment).
- **APNs key uploaded to EAS** (done via `eas credentials`), and the provisioning
  profile regenerated with the Push Notifications capability on App ID
  `com.broeking.ttp`.
- No app-code change — `utils/pushNotifications.ts` (`ensurePushPermission`,
  `set_push_token`) and the server `push_delivery` path were already in place; they
  just never got a token because registration threw without the entitlement.

## Verify on device (required — sim can't get push tokens)

1. Install build 82 on a real device.
2. Open the **Friends tab** (a social surface that calls `ensurePushPermission`).
3. Accept the iOS permission prompt.
4. Confirm a `push_tokens` row landed for the user (`set_push_token`), then send a
   test push (friend request / trade answer) and confirm it arrives.
