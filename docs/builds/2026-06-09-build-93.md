# Build 93 — 2026-06-09

## Headline

Hotfix: the app no longer freezes on launch when multiple notifications are
queued, the home tickle can no longer be rolled back by a side-effect fault,
and over-cap tickle balances are no longer confiscated on trade fulfillment.
Shop items outside today's rotation now explain themselves.

## App freeze on open — the launch-popup wedge (P0)

- **Symptom (user-reported, exact):** with multiple launch notifications
  pending, tapping "OK" on the first popup left the second one never appearing
  and the whole app frozen — every touch eaten.
- **Root cause:** each launch popup is its own native iOS `<Modal>`, and iOS
  presents only one per window. The build-90 PopupQueue handed off on a fixed
  380ms timer, and dismiss handlers unmounted a still-presented modal abruptly
  (`WhileAwayModal` hardcoded `visible`). When UIKit teardown outlasted the gap
  (launch-time JS saturation), the next modal presented *invisibly* and
  intercepted all touches (RN new-arch facebook/react-native#50152). Build 92's
  `nudge_trough` made multi-popup launches common (announcements to every
  friend), which is why it suddenly hit everyone.
- **Fix (client):** `PopupQueue` handoff gap 380→700ms (`POPUP_HANDOFF_GAP_MS`)
  plus a two-phase dismiss — `release()` flips the native modal hidden so UIKit
  genuinely animates it out, then the unmount follows 500ms later
  (`POPUP_TEARDOWN_MS`; beat < gap is the load-bearing invariant). All 5 root
  launch popups (schism / finale / while-away / achievements / allegiance) are
  now mounted-with-`visible`-driven instead of conditionally yanked.
  Achievements still advance one-per-OK. Verified: tsc clean, 207/207 tests,
  adversarial trace of the exact repro.
- **Follow-up (filed, not in this build):** preemption transitions in the queue
  are still gap-less — rare (needs a higher-priority popup resolving while
  another is presented), pre-existing since build 90, strictly improved here.

## Home tickle hardening — "I can't tickle my own pig"

- **Server (`20260624`, ⚠️ push with this build):** the core tickle
  (`item_count--`, `counter++`, `tickles_earned++`) now commits
  unconditionally; happiness, season-XP, and the lucky-pig daily block (the one
  path the visit tickle doesn't share) are each wrapped in their own
  `BEGIN…EXCEPTION` savepoint. A side-effect fault logs a WARNING instead of
  silently rolling back the whole tickle.
- **Client (this build):** a failed tickle RPC now shows "That tickle didn't
  take" instead of silently doing nothing (optimistic animation previously
  played even when the server rolled back).
