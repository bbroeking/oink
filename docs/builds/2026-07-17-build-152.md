## Sentry triage (the reason this build exists)

- **Fixes REACT-NATIVE-7 / REACT-NATIVE-8** — the notification warm-tap
  crash ("Attempted to navigate before mounting the Root Layout", 16 users,
  escalating, plus its native C++ JSError mirror) is spec 18, in this build:
  taps drain popups before navigating, consume-once, defer pre-mount.
- **Symbolication wired in** (why the four EXC_BAD_ACCESS issues are all
  `<unknown>` frames): the Xcode "Bundle React Native code and images" phase
  now runs through `sentry-xcode.sh` (JS source-map upload) and a new
  "Upload Debug Symbols to Sentry" phase uploads dSYMs. Config in
  `ios/sentry.properties`; auth token in `.env.sentry-build-plugin`
  (gitignored). First build with this = first symbolicated native crashes.
- **Fixes REACT-NATIVE-2** — leaderboard titles-join fallback now logs a
  warn breadcrumb with the real error message/code instead of an error-level
  `[object Object]` (4.3k noise events).
- **Fixes REACT-NATIVE-6** — "Network request timed out" now matches the
  transient-network classifier in `utils/rpc.ts` (warn breadcrumb, not a
  Sentry error).
- **REACT-NATIVE-1 (IAP "Invalid API Key") NOT fixed in this build** — root
  cause found: `eas.json` ships a placeholder RevenueCat key and RevenueCat
  has no App Store app configured (Test Store only). Blocked on the
  App Store Connect In-App Purchase Key (.p8) to finish RC setup; the real
  `appl_` key lands in a follow-up build.
