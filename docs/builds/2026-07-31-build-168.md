## Headline

Barn updates are dismissible, the Truffle Patch can oink when it reopens, and
the safe commuter schedule is ready for controlled testing.

## User-facing

- Barn update cards now have **Clear all**, which dismisses the current batch
  without erasing active effects; a new or changed batch can appear again.
- Guarded Truffle Patch surfaces can schedule one deduplicated local reminder
  for the next opening; a completed real dig clears the pending reminder.
- The Archery Bow now equips in Rosie's held-item slot instead of replacing her
  hat.

## Internal

- The four-window commuter clock is server-authoritative and accepts no phone
  time or UTC-offset argument in privileged RPCs.
- Both client and server support the current uniform schedule and the dormant
  Eastern commuter schedule, allowing the migration to deploy without changing
  behavior for the live binary.
- Commuter clock tests cover all four windows, the overnight gorge, Eastern DST,
  latest seeded-board/receipt behavior, and anonymous-function denial.

## Migrations

- `20260798000000_fix_archery_bow_slot.sql` — classifies `archery_bow` as held
  and moves already-equipped bows from `active_hat_id` to `active_held_id`.
- `20260799000000_server_clock_commuter_windows.sql` — installs the
  backward-compatible server clock and carries the latest rooting RPCs. It does
  not activate the commuter schedule.

Both migrations were pushed successfully on 2026-07-31. A subsequent dry run
reported the remote database up to date. Public reads confirmed the Bow is
`held` and `feeding_schedule` remains the legacy
`{window_secs:28800, open_secs:14400, offset_secs:0}` value.

## Known issues

- The candidate is built from a large dirty working tree rather than a commit.
  The fingerprints above preserve evidence, but provenance is weaker than a
  clean tagged build.
- Changing a phone's wall clock can make its local countdown/reminder inaccurate.
  It cannot open or submit another board: server time remains authoritative.
- The commuter schedule is intentionally dormant. Activation requires a
  separate explicit database go after compatible-binary device testing and a
  rollout decision for older clients.
- Real-device pre-ship smoke, notification permission/delivery/routing, Barn
  dismissal interaction, smallest/largest layouts, Dynamic Type, VoiceOver,
  reduced motion, offline/reconnect, auth recovery, purchase/restore, links,
  camera paths, and Sentry inspection remain pending with Brian.
- Production permits Sentry symbol upload failure and excludes symbols, so
  crash symbolication may be reduced.
- App Store reviewer-account and previous live-build confirmation are pending.
