# Build 78 — 2026-05-30

## Headline

Universal Links wired up. Tapping a friend's `ticklethepig.com/r/<code>`
link now opens the app directly and pre-fills the referral code in
onboarding. The reward + redemption layers were already live in prod;
this build finally closes the distribution gap.

## User-facing

- **Tap your friend's referral link → app opens directly.** Previously
  every shared `ticklethepig.com/r/<code>` link dead-ended in Safari
  because the app wasn't associated with the domain. The Universal Link
  entitlement is now compiled in; tapping a link in iMessage / Notes /
  any non-Safari app opens TTP and the onboarding code field pre-fills
  with the friend's code.
- **Referral code-entry screen fix.** Rosie's hero image was vanishing
  on the referral onboarding step (percentage width + aspectRatio
  collapsing in this layout). Now renders correctly.

## Internal

- `app.json`: added `ios.associatedDomains: ["applinks:ticklethepig.com"]`.
  Apple checks this against the AASA file at
  `https://ticklethepig.com/.well-known/apple-app-site-association`
  (Team ID `Z8F75879GQ`, bundle `com.broeking.ttp`) to verify the
  association at install time + every link tap. The AASA is served
  from the `landing/` static site, deployed at the apex via Vercel.
- `app.json`: renamed URL scheme `myapp` → `ticklethepig`. No code or
  auth flow referenced the old scheme — verified via grep + checked for
  `redirectTo` / `makeRedirectUri` usage. Just hygiene.
- `components/ReferralCodeEntry.tsx`: hero Rosie image switched from
  `width: "55%" + aspectRatio` to explicit pixel dimensions derived
  from screen width. The percentage-with-aspectRatio combo was
  collapsing to zero height because the cardWrap below is short — Yoga
  drops the aspect-derived height when the hero is mostly empty. Same
  pattern works in SupaAuth because that screen's tall Apple-auth card
  constrains the hero.
- `landing/` (new directory): static site deployed at ticklethepig.com.
  - `.well-known/apple-app-site-association` — the AASA file.
  - `index.html` — landing page for uninstalled users; parses
    `/r/<code>`, displays + pre-warms clipboard, links to TestFlight.
  - `og.png` (1200×630) — OG link preview card; generator at
    `scripts/gen_og_image.py` is deterministic + reproducible.
  - `vercel.json` — rewrites `/r/*` → `index.html`; AASA served as
    `application/json` with no redirect (Apple's spec is strict).
- `scripts/diagnose-referral.sql` — one-paste diagnostic for "my friend
  used my code and I got nothing" reports. Returns the invitee's state
  plus a derived `gate_state` column that names exactly which condition
  is blocking the gate.
- `supabase/tests/01_referrals_gate.sql` — pgTAP integration test that
  exercises the full referral flow end-to-end against a local Supabase.
  Regression net so a future migration that redefines
  `update_profile_and_item_count` can't silently drop the engagement
  gate block.
- Docs: `docs/referrals-overview.md` (canonical "how it all works"),
  `docs/referral-distribution.md` (deep-linking + TestFlight + domain),
  `docs/referrals-debug.md` (diagnostic playbook),
  `docs/referral-feedback.md` (spec for the inviter-side celebration
  modal — not built in this build, separate phase).

## Verification after install (real device, TestFlight)

The associatedDomains entitlement is compiled in — the verification
happens at install time when Apple fetches the AASA via its CDN.

1. Install the build via TestFlight on a real device. (Universal Links
   are flaky in the simulator; a real device is required.)
2. **Optional but useful:** enable Settings → Developer → Associated
   Domains Development to bypass Apple's AASA cache during testing.
3. Send yourself `https://ticklethepig.com/r/ROSIE-K3T9` in Messages.
   Tap the link (do NOT type it in Safari's address bar — typed URLs
   never trigger Universal Links).
4. Expected: app opens directly; the deep-link handler in
   `app/_layout.tsx:388` fires; signed-in users see an Apply prompt;
   signed-out users see the code stashed for onboarding pre-fill.
5. Full test plan: `docs/referrals-overview.md` and the test-cases
   section in the earlier session walkthrough.

## Known issues

- **Inviter-side completion celebration not built yet.** When a
  friend's referral completes (they cross the engagement gate), the
  inviter only gets a push (if they enabled it) and a silently-
  incrementing counter on the Account card. The
  `ReferralCompletedModal` + "N friends on their way" pending line are
  spec'd in `docs/referral-feedback.md` but deferred to a later build.
- **Push permission only requested on Friends tab.** An inviter who
  never visited Friends won't receive the completion push. Also flagged
  in the referral-feedback spec for follow-up.
