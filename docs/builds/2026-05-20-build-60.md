# Build 60 — 2026-05-20

## Headline

Push notifications + 24-hour trade cooldown.

## User-facing

- **Push notifications for Tickle Trade events** — you'll get a push
  when a friend asks for tickles, fulfills your request, or thanks
  you. Tapping the push opens the Trade modal directly.
- **First-touch permission flow** — iOS push prompt fires the first
  time you open Friends or tap the 🤝 trade pill, not on app launch.
  Permission grant rate is better when tied to a real social moment.
- **24-hour cooldown between trades with the same friend** — after
  any trade between you and a friend, neither of you can open a new
  one for 24 hours. Prevents ping-pong farming and keeps trades
  feeling deliberate.

## Internal

- `expo-notifications@~0.29.14` installed.
- New `utils/pushNotifications.ts` — `ensurePushPermission()`
  coalesces concurrent calls, caches token in AsyncStorage, persists
  via `set_push_token` RPC.
- `app/_layout.tsx` — `Notifications.addNotificationResponseReceivedListener`
  routes taps with `data.screen='trade'` to Barn home.
- `Friends.tsx` + `Barn.tsx` — call `ensurePushPermission()` on
  social-surface focus (Friends tab) + on Trade pill tap.
- `tickle_trades_push` AFTER trigger on the table builds the right
  payload per state transition (INSERT pending → notify target;
  fulfilled → notify requester; repaid → notify target; cancelled →
  silent). All trigger work wrapped in EXCEPTION so a push delivery
  failure can never roll back the underlying trade transaction.

## Known issues

- Push delivery requires APNs key configured via `eas credentials`
  (user-side one-time step). Without it, `pg_net` posts succeed but
  Expo returns a `DeviceNotRegistered`-style receipt. Inspect via
  `SELECT id, status_code, content FROM net._http_response ORDER BY created DESC LIMIT 5;`.
- iOS simulator can receive push since iOS 16, but you must be
  signed into an Apple ID in Settings on the sim. Real device via
  TestFlight is the more reliable test target.
