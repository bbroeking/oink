# Build 89 — 2026-06-07

## Headline

Two login-flow bug fixes: launch notifications no longer glitch/stick when
several land at once, and the referral-code step is skipped for everyone.

## What changed

- **Launch popups queue one at a time (no more stuck modal).** The launch
  sequence (alignment schism → judgement finale → "while you were away" notes →
  achievement reveals → allegiance pick) cleared one popup and mounted the next
  in the *same* render frame, so two native `<Modal>`s overlapped during the
  dismiss animation — on iOS that left the user unable to get past one. Now a
  `modalGap` gate holds a short beat after each dismiss so the outgoing modal
  fully unmounts before the next mounts; only ever one at a time. Also fixed the
  finale/schism guard so those two can't co-mount.
- **Referral code-entry is skipped for now.** The forced onboarding referral step
  is bypassed (`needsReferralStep` always false), so no user is gated by it. The
  Skip button + redemption code are untouched and one comment re-enables the step.

## Internal

- `app/_layout.tsx`: `modalGap` state + `closeModal()` helper; every launch-modal
  render gated on `!modalGap`; `finale` now requires `!schism`.
- `app/(tabs)/_layout.tsx`: `setNeedsReferralStep(false)`; dropped the unused
  `hasSeenReferralStep` import.

## Not in the binary

The happiness rebalance + social-XP migrations (`20260612`, `20260613`) are
server-side and already pushed to prod — no client change rides in this build.
