## Headline

Leaving a dig from its tally no longer freezes the app.

## User-facing

- **The app no longer freezes after a dig.** Since build 192 (the tally became a sheet and the dig started sliding out as a whole screen), tapping *Back to the Barn* on the tally could leave the app looking normal but ignoring every tap until it was force-quit. The tally now slips away first and the patch follows it; the Barn is live the moment it appears. The same fix covers the close chip while the tally is up and the accessibility escape.
- **Tapping a notification mid-dig waits its turn.** A push tapped while the patch is open (or any full sheet is up) no longer tears the screen out from under it. The tap is remembered and lands as soon as the sheet closes.

## Internal

- **Root cause.** On RN 0.86 Fabric (iOS) the tally (`DigReceiptSheet`, a native `Modal`) is presented FROM the dig's own full-screen `Modal`. Closing the dig flipped the outer Modal's `visible` while the inner was still up; UIKit resolves the outer's `dismissViewControllerAnimated:` to "dismiss the topmost presented child", so it dismissed the SHEET, fired the outer's `onDismiss`, and left the outer view controller presented with an emptied React tree — invisible, over the whole app, swallowing every touch. No error, no log line; Sentry sees nothing (the app is touch-blocked, not hung). Repro signature: `idb ui describe-all` after the close returns an empty tree (root + dev gear only).
- **`components/mudwar/SnoutDeepDig.tsx`** — `leave(then?)`: with the receipt up, parks the close in `afterLeaveRef`, sets `leaving` (the sheet renders `visible={false}` with `animationType="none"` so the dig's own slide is the one exit motion), and finishes from the sheet's `onDismiss` or a `RECEIPT_RELEASE_MS = MOTION_DURATION.modal * 3` fallback for hosts that never report (Android). `exit` and `join` go through it; a new `registerLeave` prop routes the host's own close (accessibility escape / hardware back) through it too. With no sheet up (the X mid-dig) the dig closes directly, as before.
- **`components/mudwar/SnoutDeepSheets.tsx`** — `LedgerSheet` / `DigReceiptSheet` forward `onDismiss` and accept `animationType`.
- **`components/mudwar/useFeedingCta.tsx`** — passes `registerLeave` to `SnoutDeepDig` (the classic `TrufflePatch` already had it).
- **`components/ui/PopupQueue.tsx`** — `useUnmanagedModalHold` now outlives `open` by `POPUP_HANDOFF_GAP_MS`, so a queued popup can't present into the closing sheet's own native dismissal (the wedge on the way OUT). New `usePopupHeld()` exposes the hold reactively (a `held` state mirrors `holdsRef`).
- **`app/_layout.tsx` + `utils/notificationRouting.ts`** — `planTapRoute(screen, routerReady, modalHeld)` defers a push tap while an unmanaged Modal holds the queue; the pending route flushes when `popupHeld` drops (the flush effect gained the `!popupHeld` condition). Before this, `routeToPath` only checked for a *presented* popup, so a warm tap during a dig ran `router.replace` immediately, the Season tab lost focus, `useFeedingCta`'s `visible` dropped, and the outer Modal hid under a live sheet — the same wedge by another door.
- Tests: `__tests__/digModalExit.test.ts` (four source-contract cases for the leave order, the `registerLeave` route, the sheet's `onDismiss` forwarding, the hold's tail), `__tests__/PopupQueue.test.tsx` (the latch outlives close by exactly the gap; `usePopupHeld` follows it), `__tests__/notificationRouting.test.ts` (held → defer; the layout wires the flag and gates the flush).
- Memory note for future sessions: `project_nested_modal_dismiss_order` — never close a host Modal with a child sheet up; hide the child first, close from its `onDismiss`.
