★ Tickle the Pig · design system v1
Rules of the system
How every element is built, named, behaves, and is kept honest. Short on purpose — a rule that needs a second explanation is the wrong rule.
★ 1

Composition law

A screen is: PageBackground → PageHeader → sections, each section a SectionHeader followed by Stickers, ListRows, or a Grid of Stickers, and at most one primary Button per screen. Sheets, Dialogs and Ceremonies float above through one of the three modal shapes. Nothing else exists. If a screen needs something the list lacks, the system grows first and the screen uses it second.

★ 2

Token law

  • No literal styling values in screens or components. Color from UI_COLORS (roles) or WHIMSY (fills); type from TYPE; size from SPACE / RADII / BORDER; depth from the two shadows; alpha from OPACITY / TINT; time from MOTION.
  • A missing token is added to theme.ts with a dated comment, never inlined. Every token names its job in one line.
  • Primitives are the only place a token becomes a pixel. Button owns its SIZE_MAP; Sticker owns radius and border; screens pass variants and slots.
  • Lint enforces it. An ESLint rule flags raw hex, rgba(, bare fontSize, borderRadius, borderWidth, padding/margin/gap numbers, and opacity literals outside constants/theme.ts and components/ui/. Existing sites are grandfathered by file until migrated under "leave it better".

★ 4

Behaviour law

  • The world responds now. Every tap has feedback inside MOTION.tap (120 ms); server truth reconciles after. A cleansed curse vanishes on tap, a claim animates on tap.
  • Modals never stack. Everything that can appear at launch enters through PopupQueue at a declared priority. A sheet may present one nested dialog through its overlay slot, nothing more.
  • Spend, leave, rename, purchase go through ConfirmDialog with the concrete number on the confirm label. Cancel is always the left, ghost button.
  • Motion is springy and has a rest pose. Decorative loops run through useMotionPolicy and stop at a still frame under Reduce Motion; state changes still explain themselves without motion.
  • Feelings are sprites, progression is numerals. Mood, hunger, warmth: shown. Snouts, finds, streak days, tiers: numbered, in Caprasimo.
★ 5

Accessibility law

  • Every tappable is ≥ 44 pt or carries hitSlop to 44, and has accessibilityRole + accessibilityLabel (+ State when it has one). IconButton and Button enforce this; hand-rolled Pressables are the gap (28 of 98 files carry none).
  • Text pairs are AA on their surface: ink / mute on every pastel; accent only on paper, cream, rose; barkText on bark; goldInk on gold. muteSoft is never body text.
  • Type scales to 200 %. Paper grows with it; fixed heights on text containers are a defect.
  • Icon and Glyph carry a label or are marked decorative. Emoji never render.
★ 6

Naming law

  • Technical names in code (activeEffects, race), cozy names on screen (Hoofprints, Dig-Off). One concept, one screen name, everywhere.
  • Kickers are lowercase hand (★ this week) or uppercase pill (★ YOUR HERD); titles are Title Case for proper nouns and sentence case otherwise; buttons are sentence case verbs.
  • ★ ✦ · are typography and stay Text. ✓ ✕ ♥ are semantic and render through Icon / Glyph.
  • Variants are named by tone (sun, rose, bark) or job (primary, locked), never by hex or by screen.
★ 7

Web parity law

Landing, analytics dashboard and every future web surface consume a generated tokens.css emitted from constants/theme.ts — the same names as CSS custom properties, the same values, the same four fonts. No HTML file re-declares .sticker; one shared stylesheet does.
