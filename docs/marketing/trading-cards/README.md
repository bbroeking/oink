# Tickle the Pig trading-card mockups

Four print-sized card fronts (1500×2100, the 2.5×3.5-inch trading-card ratio)
are generated by:

```sh
node scripts/render-trading-card-mocks.mjs
```

## QR behavior

- `01` and `02` encode the canonical App Store listing.
- `03` encodes the live shared Ticket Taker's Cap Golden Ticket
  (`PIG-G9HJ-2EMF`, capped to 10 uses by migration `20260776`).
- `04` encodes the live shared Release Party Crown Golden Ticket
  (`PIG-GXF8-ST7N`, capped to 10 uses by migration `20260776`, expires
  at the end of September 1, 2026 via migration `20260777`).

The two reward codes were already live before these mockups were made. Rendering
the cards does not mint, reset, or otherwise mutate redemption data. The same
migration adds a lifetime ten-owner cap to each cosmetic, so future codes or
other grant paths cannot exceed the supply. Before printing a run, verify
remaining uses and expiry in Supabase. For a new campaign, mint a fresh code
with `scripts/mint-redemption-codes.mjs`, then add its URL and printed code to
the card definition.

### Mint a code for an existing item

An item does not need a new migration just to receive a later redemption
campaign. Any row already in the `hats` catalog can receive a new code:

```sh
# Discover existing catalog ids.
node --env-file=.env --env-file=.env.local \
  scripts/mint-redemption-codes.mjs --list-items

# Validate a campaign without changing production.
node --env-file=.env --env-file=.env.local \
  scripts/mint-redemption-codes.mjs \
  --item release_party_crown \
  --label "Release party cards" \
  --count 1 --max-uses 10 --expires 2026-09-01 --dry-run

# Remove --dry-run to mint the live code and QR.
```

`--item <id>` is shorthand for `--grant hat:<id>`. The tool validates the id
against the live catalog before inserting anything. Supply-limited items still
obey their item-level owner cap across every code and grant path.

The PNGs are delivery previews. The SVGs preserve vector text, borders, and QR
modules and are the better source for a print shop.

`contact-sheet.png` is regenerated alongside the individual cards for a quick
visual review.

## Nine-up print sheets

Generate US Letter sheets with nine standard 2.5×3.5-inch cards:

```sh
python3 scripts/render-trading-card-print-sheets.py
```

This produces:

- `output/pdf/tickle-the-pig-cards-mixed-9up.pdf` — one balanced mixed sheet.
- `output/pdf/tickle-the-pig-cards-full-sets-9up.pdf` — four pages, nine copies
  of one design per page.

Print at **Actual size / 100%**. Disable "Fit to page" so the physical card
dimensions remain correct. Short exterior crop ticks mark every cut line.

## Rosie's Loadout

The playable equipment-battler armory is generated separately:

```sh
node scripts/render-rosies-loadout-cards.mjs
python3 scripts/render-trading-card-print-sheets.py
```

The nine illustration-first fronts live in `equipment-game/`. Their shared back
is `card-back-crown-reward.png`; it carries the live Release Party Crown reward
link for the Shop scanner. Keeping all backs identical preserves hidden
equipment choices during play. The redemption landing page provides an App
Store path for players who have not installed the game.

The duplex printable armory is `output/pdf/rosies-loadout-armory-9up.pdf`:
page 1 is the nine fronts; page 2 is the mirrored back sheet. Print at **Actual
size / 100%**, double-sided, **flip on long edge**. A front-only fallback is
`output/pdf/rosies-loadout-armory-fronts-only-9up.pdf`.

Each player builds three loadouts from Head, Held, and Aura equipment. Cards
03, 06, and 09 are Special Illustration treatments—one per slot, with
unchanged gameplay stats. Rules and the playtest plan are in `MICROGAME.md`.

The Crown is capped to ten owners across every copy and every grant path. A
complete nine-card sheet therefore contains nine opportunities to claim the
same reward; printing a second sheet does not increase the digital supply.

The SVG card sources reference the high-resolution paintings in
`equipment-game/art/`. Keep that folder beside the SVGs when packaging them.
The generated PNGs and PDF are self-contained print artifacts.

## Duel-game redesign

The current PDF remains the quick three-card-loadout microgame. The next
playable version uses the existing nine illustrations as the Gear half of a
deeper dual-use card game.

- [`MAPLESTORY-ITCG-RESEARCH.md`](./MAPLESTORY-ITCG-RESEARCH.md) reconstructs
  the original 2007 game's rules from its Wizards rulebook and Set 1 FAQ.
- [`ROSIES-LOADOUT-DUEL-SPEC.md`](./ROSIES-LOADOUT-DUEL-SPEC.md) translates
  the useful structure into an original 18-card-per-player Rosie equipment
  duel.

The redesign replaces the one-step loadout comparison with visible leveling,
card-or-Training decisions, persistent Head + Held + Aura slots, Critters that
attack or protect, and deterministic damage. It has not yet replaced the
rendered card fronts or print PDFs.

## Base set: 88 cards

[`base-set-84/README.md`](./base-set-84/README.md) expands the prototype into
**Rosie's Loadout: The Hunger in the Bog**, an 88-card first set:

- 6 Legends;
- 27 Gear cards;

- 16 Stunts; and
- 7 Places.

The full rules text, Training strip, flavor, rarity, style, rank, and art status
for every card live in

`node scripts/validate-trading-card-base-set.mjs` to verify the set counts,
balance budgets, unique identifiers, and source-art paths.
